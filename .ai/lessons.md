# Lessons Learned

Long-term memory for AI agents working in this repo. Read this before starting any task.

- One entry per lesson, **newest at the top**, written as an actionable rule.
- Put longer write-ups in `lessons/YYYY-MM-DD-slug.md` and link them from the entry.
- Update or remove entries that become wrong or obsolete. Don't add duplicates.

Format:

```markdown
- **YYYY-MM-DD — <Short title>** `#tag` — <One or two sentence actionable lesson.> [details](lessons/YYYY-MM-DD-slug.md)
```

## Lessons

- **2026-10-27 — A rule that needs a "place" must say what to do when there is none** `#docs #process` — "Undoable means the person can restore it from a place the toast names" left the probe guessing for "hide a past session" (no such place). When a rule depends on something that may not exist, add the other branch and an example of it (here: use the dialog, or build the place first).
- **2026-10-27 — A probe's RULE count overstates once the rules mention the probe's own screen** `#process #docs` — Probe 3 labeled `#31`, `#11`, `#12`, `#14`, `#15`, `#17` as RULE although they were written around mentors and favorites. Report the guess count and ask the agent which RULE labels were copied by analogy; fix the wording, not the count.
- **2026-10-27 — A helper exported from a `.stories.tsx` file becomes a story** `#storybook` — `export const FavoritesDemo` in a stories file showed up in `index.json` as a story and changed the screen count. Put shared demo wrappers in `packages/ui/.storybook/docs/` and keep only stories (and `meta`) exported from `stories/**`.
- **2026-10-27 — Focus after a list change: keep the target in a ref and re-run the effect on a counter** `#ui #accessibility #react` — An effect keyed on the `mentors` prop missed the focus move when the parent updated the list before `onRemove` resolved (the effect ran while the target was still unset), and `setState` inside the effect fails the `react-hooks/set-state-in-effect` lint. Store the target in a ref when the server confirms, bump a `removed` counter, and run the effect on `[mentors, removed]` once the list has shrunk.
- **2026-10-27 — Run Prettier only on files you created** `#process #tooling` — `prettier --write packages/ui/src/components/mentors` reformatted two unrelated test files. Pass explicit new file paths, then `git diff --stat` and revert collateral changes.
- **2026-10-27 — Run Vitest from the repo root** `#test #tooling` — `npx vitest run src/...` inside `packages/ui` fails every test (the config and the jsdom setup live at the root). Use `npx vitest run packages/ui/src/...` from the root.
- **2026-10-26 — A story next to the component is never shown** `#storybook #docs` — `.storybook/main.ts` loads only `stories/**`. Put a concept's stories in `packages/ui/stories/product/<concept>/` and the component in `packages/ui/src/components/<concept>/`; the rule is now in `AGENTS.md`.
- **2026-10-26 — Check the current branch before every push** `#process #git` — "Push to the PR branch" ran `git push` while the checkout was on `main` (the PR had been merged), so the commit landed on `origin/main`. Run `git branch --show-current` as a separate step, confirm it is the intended branch, and push with an explicit `origin <branch>`.
- **2026-10-25 — Sweep every story at 320 px, not a sample** `#storybook #responsive` — A page claimed the status badge and tooltip wrap; at 320 px both overflowed. Documentation claims about narrow screens must come from a sweep of all stories. In a centered story layout, `max-w-full` on a child can still overflow. Give the story `layout: "padded"`.
- **2026-10-25 — A `{ ... }` outside a code span breaks an MDX page** `#storybook #docs` — `import path { Button }` in a table cell made MDX evaluate `Button` and the whole page failed with "Button is not defined"; the build still passed. Put anything with braces inside a code span, and load every new MDX page in the browser, not only the build.
- **2026-10-25 — `check:tokens` scans MDX too** `#tooling #docs` — Documentation pages that quote bad examples (a palette class, a hex colour, an arbitrary value) add findings. Describe them in words in `stories/**/*.mdx`; quoting them is fine in `docs/*.md`, which the script does not scan.
- **2026-10-25 — Direct children of a `dl` are `dt` and `dd` only (a wrapping `div` may hold them)** `#ui #accessibility` — `MetricRow` put a `dt` and a `p` in a nested `div` inside a `dd` sibling; axe `definition-list` failed. Use one `div` per group with `dt` and one or more `dd`, and place them with grid classes, not extra wrappers.
- **2026-10-25 — Don't write coverage claims about screens from memory** `#process #docs` — My first draft of the "Screens and state maps" page said every screen had certain states, and listed pattern users, without checking. Two entries were wrong (Join has no form hook; the E01 count was 26, not 28). Count from the built `index.json` and grep for usage before writing a table of facts.
- **2026-10-25 — Count `h1` inside `#storybook-root` when checking a story page** `#storybook #test` — The preview iframe has its own hidden `h1` elements, so `document.querySelectorAll("h1")` returned 3 on every story and produced 210 false problems. Query `#storybook-root h1`.
- **2026-10-25 — macOS `sed -i` takes the next argument as the backup suffix** `#process #tooling` — `sed -i 's|a|b|' file` failed with "undefined label" and silently left the script unchanged, so the check ran again with the old code. Use a Python replace with `assert old in s` for scripted edits (same rule as the Prettier lesson), and confirm the new text with grep.
- **2026-10-25 — A scripted text replace after Prettier can silently do nothing** `#process #tooling` — I ran Prettier on new files and then used Python `str.replace` with the pre-Prettier text; the replace did not match, no error was raised, and the build failed later (`Heading` undefined). After any scripted edit, assert that the old text was present (`assert old in s`) or grep for the new text.
- **2026-10-25 — A card or row inside a page needs a configurable heading level** `#ui #accessibility` — A fixed `h3` in `BookingCard` and `NotificationRow` under a page `h1` failed axe `heading-order`. List items that carry a heading take `headingLevel` (default 2) so the page decides the outline.
- **2026-10-25 — Use `useSyncExternalStore` for browser-only values, not state set in an effect** `#react #lint` — `useState` plus `setState` in `useEffect` for the viewer's time zone tripped `react-hooks/set-state-in-effect`. `useSyncExternalStore(subscribe, browserValue, serverValue)` gives the same "UTC on the server, real zone after hydration" without a flash or a lint exception; cover the server snapshot with `renderToString` in a unit test.
- **2026-10-25 — A hook option that is a bare boolean breaks when passed to `onClick`** `#ui #react` — `reset(keepStatus = false)` given as `onClick={form.reset}` receives the click event, which is truthy, so the reset silently kept its status. Take an options object (`reset({ keepStatus: true })`) and call `() => form.reset()` from handlers.
- **2026-10-25 — `@devmentor/ui` exports only `.tsx` under `components/*`** `#ui #monorepo` — A plain `.ts` module there (`pricing.ts`, `windows.ts`) cannot be imported through `@devmentor/ui/components/...`; TypeScript looks for `.tsx`. Import it by a relative path inside the package (stories, tests) or move the constants to `@devmentor/core` when it can take them.
- **2026-10-25 — A busy `Button` ignores the pointer, so a double-submit test must press Enter** `#storybook #test` — `aria-disabled:pointer-events-none` makes `userEvent.click` throw on a loading button. Prove "a second submit sends nothing" by pressing Enter in a field while the first request is pending.
- **2026-10-25 — A Tailwind `outline-none` cancels `outline-2` on the same element** `#ui #tailwind` — In Tailwind 4 `outline-none` sets the outline style to none, so `data-highlighted:outline-2` drew nothing (measured: `outline-style: none`). Use `outline-0` plus a variant that sets the width, and measure `getComputedStyle(...).outlineStyle` for focus and highlight states.
- **2026-10-25 — Stories rendered in their own docs frame don't get the theme** `#storybook #theme` — `inline: false` stories load a second preview whose initial globals say light, and they post that to the docs page, flipping it back to light (flaky). In `preview.tsx` a frame inside `.sbdocs` follows the parent's `dark` class and sets no `theme` global, and the global handlers ignore events without one. Check dark through the manager UI, not only `iframe.html`.
- **2026-10-25 — Check the exit code and count of a gate script, not just that it printed** `#process #tooling` — Prettier wrapped `var(\n--x\n)` in `tokens.css` and `contrast.mjs` crashed; I read the "0" output as success. The resolver now tolerates whitespace. After any formatter run, rerun `node packages/ui/scripts/contrast.mjs` and expect every pair to say `ok`.
- **2026-10-25 — Measure click targets in the browser, don't assume them** `#ui #accessibility` — A 20px checkbox in a one-line Field row gave a 20px-high label, below WCAG 2.5.8's 24px. Measure `getBoundingClientRect` of the label row in a story and pad the label (`py-inline`) instead of trusting the pseudo-element hit area.
- **2026-10-25 — `cn` drops custom token utilities unless configured** `#ui #tailwind` — The `cn` package merges like tailwind-merge: it treats `text-conversation` (a font size) as a text color and removes it next to `text-foreground`. `packages/ui/src/lib/utils.ts` extends the theme with the token names; add new token utilities there and import `cn` from `lib/utils`, not from `"cn"`.
- **2026-10-25 — Don't run Prettier over `packages/ui/src` wholesale** `#process` — It reformatted untouched files (hero, backend feedback, card tests). Format only files you changed, and check `git status` for stray modifications afterwards.
- **2026-10-25 — First `test:stories` run after edits can fail to import the setup file** `#storybook #test` — "Failed to import ... setup-file-with-project-annotations" is a stale Vite cache. Rerun; if the second run fails too, it is real.
- **2026-10-25 — Storybook in this monorepo needs three explicit fixes** `#ui #storybook` — `@storybook/nextjs-vite` does not run Tailwind, so add `@tailwindcss/vite` in `viteFinal`. Derived tokens (`--card-foreground: var(--foreground)`) resolve where they are declared, so declare them on every theme scope (`:root, .light, .dark`) or nested theme previews keep stale values. ESLint must ignore `storybook-static/`, or it lints the build output.
- **2026-10-25 — Check contrast after component opacity is applied** `#ui #accessibility` — Calculate text, boundary and focus contrast against actual surfaces after compositing opacity modifiers; passing base colors can still fail in tinted destructive-button states or a half-opacity focus ring. Token declarations alone do not fix those component treatments.
- **2026-10-24 — Discovery never reads or edits the engineering standards** `#discovery #process` — `.ai/docs/engineering-standards.md` is general best practice and its relevant parts are already in `AGENTS.md` and the code. Don't cite it in a product brief, treat it as a source of conflict, or edit it; check `AGENTS.md` and the code for actual constraints.
- **2026-10-24 — Don't name a signer from research exports** `#discovery` — I wrote that a person named in the research exports signs the Definition of Ready; the user said no such person exists and that they sign. Use the role (Product owner) and ask when a name is not in a decision record.
- **2026-10-24 — Verify research summaries against their source** `#discovery #evidence` — Recompute figures from supplied raw exports before quoting their reading aids, and preserve the original question's scope when reporting survey behavior. Interpret status fields using their collection context: no recruitment invitation is not the same as no research contact.
- **2026-10-22 — Count discovery markers as whole lines** `#process #tooling` — When validating discovery sections in `SDLC.md`, anchor marker checks to entire lines. The Amending section also quotes marker strings in inline code, so counting every occurrence overcounts the actual section boundaries.
- **2026-10-22 — Root scripts need their own place in the test gate** `#test #tooling` — `vitest.config.ts` only measured `packages/*/src`. Code under root `scripts/` is covered because its `include`/`coverage.include` list `scripts/**`. Vitest 5 has no per-glob environment, so each `scripts/**` test starts with `// @vitest-environment node`. Keep logic behind injected adapters (`scripts/setup/system.mjs` is the only impure file).
- **2026-10-22 — `db:migration:list` shows executed migrations, not pending ones** `#mikro-orm` — To decide "is anything pending" you would need `migration:pending`, which has no script. `migration:up` is already idempotent, so run it instead of trying to skip it.
- **2026-10-21 — jsdom's URL resolves file paths against the page** `#test` — In Vitest's jsdom environment, `new URL(relative, import.meta.url)` turns a `file://` base into `http://localhost:3000/...`. Unit-test modules that resolve paths from `import.meta.url` with `// @vitest-environment node`.
- **2026-10-21 — `agent-browser` engines field is for a source build** `#test` — `agent-browser@0.39` declares `node >= 24`. That applies to compiling the native CLI. The published binary runs on this repo's Node 22. Don't bump the runtime to silence the warning.
- **2026-10-21 — Don't re-ask a request that already states the outcome** `#process` — When the user names the checks, the coverage rule, and the tools, decide the technical defaults and implement. Don't turn that into a questionnaire. They are not a programmer; explain the result in plain language.
- **2026-10-20 — Catch-all route wrappers must call `unstable_rethrow`** `#nextjs` — `notFound()`, `redirect()` and prerender signals are thrown errors. A generic `try/catch` (like `apiHandler`) would turn them into 500s. `core` can't import Next, so `createApiHandler({ rethrow })` takes it as an option and the app passes `unstable_rethrow` (`packages/app/src/http/api-handler.ts`). Also, `export const dynamic` doesn't exist under `cacheComponents`; use `await connection()`.
- **2026-10-20 — Check imported standards docs against `AGENTS.md` first** `#process` — `.ai/docs/engineering-standards.md` was written for another bootstrap (reversed dependency direction, services in `core`, `force-dynamic`, files that don't exist). Before implementing an external doc, diff its assumptions against `AGENTS.md` and the real tree, and get the conflicts decided in a spec. Don't apply it literally.
- **2026-10-20 — Check current docs before calling a dependency bogus** `#process` — I flagged the `cn` npm package as "unrelated" and removed it. It is shadcn's official class-merge package (repo `shadcn-ui/cn`). Before removing a dependency a tool added, check the tool's current docs and the package's repo and maintainer on npm.
- **2026-10-20 — `buttonVariants` must go through `cn()`** `#ui #shadcn` — `cva` concatenates classes without resolving conflicts (e.g. `border-transparent` + `border-border`), so the outline border vanished. Use `cn(buttonVariants(...))` on links. Don't use `<Button render={<Link/>}>` for navigation: Base UI adds `role="button"`.
- **2026-10-20 — shadcn CLI in this monorepo** `#ui #shadcn` — `shadcn init` fails in `packages/ui` (no framework detected), and `add` before the theme CSS exists produces broken output. Base setup is manual (deps, `globals.css`, `lib/utils.ts`). After that, run `npx shadcn@latest add <c>` from `packages/app`, and the files land in `packages/ui`.
- **2026-10-20 — `loadEnvConfig` in `next.config.ts` is a no-op** `#nextjs #env` — `@next/env` caches its first call (Next's own call, for `packages/app`), so a second call for the repo root loads nothing. Load the root `.env.local` with `process.loadEnvFile()` instead. It doesn't override real env vars.
- **2026-10-20 — `server-only` throws outside Next.js** `#db` — Importing `server-only` from code the MikroORM CLI loads crashes the CLI. Keep it in runtime entry points (`orm.ts`) only.
- **2026-10-20 — MikroORM is v7, not v6** `#mikro-orm` — v7 is ESM-only, needs Node `>=22.17`, and replaced knex with `@mikro-orm/sql` + `kysely`. Don't use v6/knex APIs from memory: check the installed `.d.ts` files (e.g. `pool`, `defineEntity`, `allowGlobalContext` in `Configuration.d.ts`). With zero entities, set `discovery.warnWhenNoEntities: false`, or init throws.
- **2026-10-20 — Next.js 16 differs from training data** `#nextjs` — Before writing Next.js code, read the relevant guide in `node_modules/next/dist/docs/` instead of relying on memory. `next dev` maintains `packages/app/AGENTS.md` (its project dir). Don't edit or remove its managed blocks; commit them.
