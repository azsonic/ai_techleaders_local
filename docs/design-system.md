# DevMentor design system (read this before building a screen)

This is the summary an AI agent reads first when it builds or changes a screen. The long version is the Storybook in `packages/ui` (`npm run storybook -w @devmentor/ui`): start at **Design system / Start here**. `AGENTS.md` links here. If this file and Storybook disagree, fix the one that is wrong and tell the user.

This file is the summary and wins when it disagrees with another page: fix the other page. Where the style comes from (provenance, not required reading): the brief `.ai/specs/product-brief.md`, the specs in `.ai/specs/`, and the course material `lekcja-06/referencje.md` (references) and `lekcja-06/tokeny.md` (tokens and contrast). Decisions made while building are in `packages/ui/POSTEP.md`. Do not invent style. If something is missing, ask, and mark your own idea as a proposal. The Product owner approves rule changes.

## Hard rules

1. Build only from `@devmentor/ui`. Use a product component if one exists, else compose base components. Do not add a component, variant or dependency that is not needed in two places and approved.
2. Every value comes from a token. No hex, rgb, hsl or oklch colors, no Tailwind palette classes (`bg-zinc-900`, `text-white`), no arbitrary values (`p-[13px]`). `npm run check:tokens` must report nothing new.
3. Every screen with data has these states: loading, empty ("nothing here yet"), error with a next step, partial data, lots of data, long text. A screen with an action also has pending, server error and offline.
4. Show success only after the server confirmed. Keep what the person entered when something fails. Prevent a double submit.
5. A label is always visible. A placeholder is an example, never the field name.
6. An error that needs action is never a toast. Use a field error, an alert or the error state.
7. A disabled control says why, in text linked with `aria-describedby`. A tooltip never holds information needed to act.
8. Color is never the only carrier of meaning. Statuses are words.
9. Both themes must work. Stories run as tests with axe errors in light and dark.
10. Call the API only through `apiCall` / `apiCallOrThrow` (`@devmentor/ui/backend/api/api-call`).
11. Product UI language is American English (`favorites`, `color`; amounts stay in `PLN`). Wording: short, direct, names the action, the outcome and the next step (P10.1). The product word for a mentor's technology is **Stack** (D07).

## Product character

DevMentor connects a developer who is blocked with an experienced mentor for a paid 25 or 50 minute text session; the goal is a written answer (N01.1). The interface is **clear**, **warm** and **focused** (C01 to C03): the main action or current status is stronger than metadata (R01.5), surfaces are warm gray, flat and opaque (R01.4, A01.1, A01.2), the conversation is the center of a session and the composer stays visible (R02.1, R02.2). It is never **cold**, **cluttered** or **generic** (AC01 to AC03).

## Patterns

| Screen type                              | Pattern                                                                                                                              |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| A form                                   | Form: `Field`, `useForm`, `FormFeedback`                                                                                             |
| A list the person filters                | Filtered list: `FilteredList` (used by `MentorDirectory` and `FavoriteMentors`); two different empty states ("no results for these filters" with Clear filters, "nothing here yet") |
| A page about one object                  | Detail view: main information and main action visible without scrolling, "does not exist or no access" state                         |
| Deleting something                       | Deletion confirmation: the object in the question, Cancel first, a verb button ("Remove window"). Something undoable (a favorite) is a direct button plus a toast, no dialog |
| A session conversation                   | Conversation: `Conversation` with `MessageItem` and `Composer`, state beside each message                                            |
| An operator changing someone else's data | Operator action: `OperatorActionDialog`, reason required (max 1000 characters), logged                                               |

All 19 screens and 145 states are in Storybook under Product / <epic> / Screens, with state maps on each epic page (E01 to E05) and on the Favorites page. E03, E04, E05 and Favorites have no specification: they are proposals.

## Rules for lists and for actions on an item

These answer the questions a list screen raises, for any object (mentors, bookings, sessions). Favorites is the worked example. Details and sources are in Storybook: Patterns / Filtered list and Patterns / Deletion confirmation.

| Question | Rule |
| --- | --- |
| Page frame | A page is an `h1` and its content inside `max-w-content`. `ScreenFrame` in `.storybook/docs` is a documentation helper, not a product component; the application shell is not designed (see "What is missing"). |
| Which component | A list the person narrows is built on `FilteredList`. A list with no filter composes the same states (loading, error, empty) itself. |
| Which filter options | A fixed list (all four stacks), never derived from the visible items, so the filter does not jump. Filters combine as "any of" (OR). While the list loads or refetches, the filter stays usable and only the list area shows the state. |
| Order | The server's order. When it is not obvious, write it in words above the list ("Most recent first"). Never a rating. A time on an item uses `LocalTime`; a metadata slot on the card is added when a second consumer needs it (see "What is missing"). |
| Heading levels | Page `h1`; an item heading is `h2` (`headingLevel`, default 2); inside a section whose heading is `h2`, items are `h3`. |
| Link to the object | The item's main text is the one link to it: a mentor's name, a booking's time (as `BookingCard` does). No second "View profile" link with the same target. Put that link inside the item's `h2`: `useItemRemoval` finds the next item to focus as `a` inside `h2`. |
| An item that is no longer available | A list shows only what is available: an item that disappeared between loads is absent and the count reflects it. A direct link to it uses the "does not exist or no access" state (Detail view). |
| Headline of a mentor | One line under the name: `text-interface text-muted-foreground`, wraps (`wrap-anywhere`), never truncated, at most 200 characters. Omit it when there is none (no placeholder). |
| Partial data on a mentor card | No headline: the line is omitted. No image: initials. No stacks: the stack list is omitted. |
| Card for an item in the person's own list | `MentorCard variant="listed"` with `headline` and `actions`: identity only, no price, no slot. |
| Action on one item | `Button variant="secondary" size="dense"`, last inside the card, under the content (never beside the name), so it also fits at 320 px. `destructive` is for irreversible actions only. |
| Name of a repeated action | Keep the visible label and add the object in `sr-only` text: "Remove from favorites" plus `<span className="sr-only">: Anna Kowalska</span>`. |
| Remove: dialog or direct | Undoable means the person can restore it themselves from a place the toast names, with no money moved, nobody notified and nothing typed lost: a direct button, a toast after the server confirmed, no Undo in the toast. Anything else needs a confirmation dialog (Deletion confirmation, with examples). Hiding an item with no place to bring it back from (a past session hidden from its list) is not undoable: use the dialog, or first build the place to restore from. |
| How to build the removal | `useItemRemoval` (`@devmentor/ui/hooks/use-item-removal`): it owns pending, failure, toast and focus. Spread its `areaProps` on the wrapper of the list. The page supplies `onRemove` and the toast words. |
| While removing | Only that item's button is `loading` ("Removing…"). Other items stay usable. |
| Removal failed | A destructive `Alert` above the filters: title "The <object> was not removed", the server's message (offline, code `network_error`: "The server did not answer. Check your connection and try again."), then "They are still in <the list>." The item stays. The alert clears on the next attempt. |
| After a removal | The count (`role="status"`) announces the new number. Focus moves to the link of the item that took its place, or to the list area when none is left. If the last item goes, the unfiltered list shows "nothing here yet"; a filtered list shows "no results for these filters". |
| Toast | One `ToastProvider` is mounted by the application shell. A component never mounts its own; a story that shows a toast wraps itself in one. |
| Action callback | `(id) => Promise<ApiResult<unknown>>` from `@devmentor/core`. It resolves with the envelope and never rejects (`apiCall` guarantees this). The page updates the list before or as `onRemove` resolves. |
| Error text of a list | `FilteredList errorMessage` says what is safe and what to do; the default is "Nothing was changed. Try again." |
| Skeleton | A skeleton copies the footprint of the item it stands in for (`MentorCardSkeleton`, or the item's own skeleton exported next to it). No free height or width utilities. |
| Where a list screen lives | In the folder of the concept it lists (mentors in a list: `components/mentors/`); a new folder only for a new concept. Its stories: `stories/product/<concept>/`, titled `Product/<Concept>/...` (an epic folder such as `e02` only for the screens of that epic), and a screen story file is named `screen-<name>.stories.tsx`. |
| Stories a list screen needs | The component's stories carry partial, lots (30) and long text; the screen's stories carry the states of its screen map. |

## If ... then use ...

| If                                                 | Then use                                                                              |
| -------------------------------------------------- | ------------------------------------------------------------------------------------- |
| An action that changes data                        | `Button` with a verb and an object                                                    |
| Going to another page                              | `TextLink` (a button never navigates)                                                 |
| Three or more commands for one object              | `Menu`; one or two commands are visible buttons                                       |
| Exactly one of two to four options                 | `RadioGroup`; five or more: `Select`                                                  |
| Several independent options                        | `Checkbox`; an on or off setting: `Switch`                                            |
| A yes or no about something irreversible           | `AlertDialog` (confirmation dialog) with the object in the question                   |
| A short task with a field or two                   | `Dialog`; bigger: a separate page                                                     |
| One value is wrong                                 | The error in `Field`                                                                  |
| Something about the page needs attention or action | `Alert` next to the content                                                           |
| Content did not load or does not exist             | `ErrorMessage` (error state) with a next step                                         |
| The server accepted something small                | `Toast`, after the server confirmed                                                   |
| Content loads from the server                      | `Skeleton` and `LoadingMessage` (text, no spinner); a waiting button: `loading`       |
| Compare columns across objects                     | `Table`; one object at a time: `Card`; dense scannable rows: a thin line between rows |
| Two to five views of one list                      | `Tabs`; other sections: links in a navigation                                         |
| Icon-only control                                  | `Button size="icon"` with an accessible name and a `Tooltip`                          |

## What to avoid

- The product's own anti-patterns (A01, NR01 to NR04): gradients, glass or blur, sparkles, cold gray with no priority, a cluttered chat shell, course progress bars, modules, certificates, star ratings and rating badges.
- Generic AI appearance: gradients in backgrounds, text and buttons; glass and blur; glow; emoji instead of icons or labels; sparkles as an AI symbol; three identical icon cards; pills everywhere (`rounded-full` on badges and buttons); a card inside a card; a shadow as the only separator; everything centered.
- Implementation mistakes: non-token values; an incidental variant; a `div` instead of a button; a placeholder instead of a label; status shown only by color; a disabled button with no explanation; a toast for an error that needs action; a tooltip with information essential for an action; "saved" shown before the server answered; `fetch("/api...")` in a component.

## Commands

Run from the repository root.

| Command                                                              | What it does                                                            |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `npm run storybook -w @devmentor/ui`                                 | Storybook on port 6006                                                  |
| `npm run build-storybook -w @devmentor/ui`                           | Static Storybook                                                        |
| `npm run test:stories -w @devmentor/ui`                              | Every story as a test, axe errors fail (add `:dark` for the dark theme) |
| `npm run check:tokens`                                               | Finds non-token values                                                  |
| `npm run check:contrast -w @devmentor/ui`                            | Contrast of every supported pair                                        |
| `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build` | The definition of done (`AGENTS.md`); `test` enforces 100% coverage     |
