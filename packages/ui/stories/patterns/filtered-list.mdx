# Filtered list

How a list that can be narrowed behaves. Built as the `FilteredList` component and used by `MentorDirectory` (E02-S01) and `FavoriteMentors`; a list of bookings or invitations with filters follows the same rules.

## Purpose

A person narrows a list, always sees what the filters are, and always knows why the list is empty.

## When to use

- The mentor directory, filtered by stack.
- Any list where a person looks for one item among many and the narrowing choices are few and known.

## When not to use

| Situation                                            | Use instead                                                                 |
| ---------------------------------------------------- | --------------------------------------------------------------------------- |
| Looking for one item by a word                       | A search field with results (not in this system yet, see "What is missing") |
| Switching between a few fixed views of the same list | [Tabs](?path=/docs/primitives-tabs--docs), as My bookings does              |
| A form that sends something                          | The [form pattern](?path=/docs/patterns-form--docs)                         |

## Rules

| #   | Rule                                                                                                         | How it is built                                                                                                    | Source          |
| --- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | --------------- |
| 1   | Filters are visible, not hidden in a menu, and one click removes one.                                        | A checkbox group "Stack". A checked box is a visible filter; unchecking it removes it.                             | R01.1, E02 spec |
| 2   | Filters apply as they change. There is no apply button.                                                      | `onSelectedChange` on every change; the page asks the server and passes the result.                                | E02 spec        |
| 3   | The number of results is written and announced.                                                              | `<p role="status">` "2 mentors" ("1 mentor"), updated when the list changes.                                       | WCAG 4.1.3      |
| 4   | A clear action is offered while any filter is set.                                                           | "Clear filters" button above the list and inside the no-results state.                                             | P10.1           |
| 5   | "No results for these filters" and "nothing here yet" are different states with different words and actions. | `EmptyState` twice: the first says to remove a filter and offers "Clear filters"; the second says why it is empty. | P10.1, R01.5    |
| 6   | Loading, error and partial data are states of the list, not of the page.                                     | `LoadingMessage` with skeleton cards; `ErrorMessage` with "Try again"; a card without price says so.               | P11.1, P12.2    |
| 7   | The order never depends on a rating.                                                                         | No rating, score or ranking appears (soonest slot first is the server's order).                                    | N02, D06        |
| 8   | The filter options are a fixed list, never derived from the visible items.                                   | `filter.options` is the full list of stacks, so the filter does not jump when the list changes.                    | Proposal        |
| 9   | While the list loads or refetches, the filter stays usable and only the list area shows the state.          | The filter fieldset is outside the loading, error and empty branches.                                              | Proposal        |
| 10  | When an item can be removed, only that item is pending, and the list is not blocked.                         | `Button loading` ("Removing…") on that item; other items stay usable. `useItemRemoval` owns this.                  | P12.1           |
| 11  | A failed action on an item is an alert above the filters that keeps the item and clears on the next try.     | `notice` slot of `FilteredList`: destructive `Alert` with the hook's `failure`; offline wording from the hook.     | P12.2, content  |
| 12  | After a removal the new count is announced and focus moves to the item that took the removed one's place.    | `role="status"` count; focus on the next item's link, or on the list area when none is left (the hook).            | WCAG 2.4.3      |
| 13  | Removing the last item shows "nothing here yet"; removing the last match of a filter shows "no results".     | The two empty states follow the filters, not the removal.                                                          | P10.1           |
| 14  | Item headings are `h2` under the page `h1` (`headingLevel`).                                                 | `MentorCard headingLevel`, default 2.                                                                              | WCAG 1.3.1      |
| 15  | Filters combine as "any of". The order is the server's and is written when it is not obvious.                | Checked stacks match any; "Most recent first" above the list when the order is by time.                            | Proposal        |
| 16  | The item's main text is the one link to the object, inside the item's `h2`.                                  | `MentorCard` links the name, `BookingCard` the time; no separate "View profile". The hook's focus move needs `h2 a`. | Proposal        |
| 17  | A list shows only what is available. An item that vanished between loads is absent and the count follows.   | The server leaves it out. A direct link to it shows "does not exist or no access" (Detail view).                   | Proposal        |
| 18  | A list's error text says what is safe and what to do.                                                        | `errorMessage` prop; default "Nothing was changed. Try again."                                                     | P12.2           |
| 19  | A skeleton copies the footprint of the item it replaces.                                                     | `MentorCardSkeleton`, or the item's own skeleton next to it; no free height utilities.                             | P11.1           |
| 20  | The order is written in one line between the count and the list when it is not obvious.                      | `description` prop of `FilteredList` ("Most recent first"). Omit `skeleton`, `loadingLabel` and `errorTitle` when a tab or page owns loading and error. | Proposal |

### Favorite mentors

The same pattern with a remove action on each card. See the [Favorites page](?path=/docs/design-system-favorites--docs).

## Code

```tsx
// Page or screen: the removal behavior lives in the hook.
const { areaProps, removing, failure, remove } = useItemRemoval({
  items: mentors,
  onRemove, // (id) => Promise<ApiResult<unknown>>, resolves, never rejects
  toast: (m) => ({
    title: `${m.displayName} removed from favorites`,
    description: "You can save this mentor again from their profile.",
  }),
});

<div {...areaProps}>
  <FilteredList
    items={mentors} // the server's filtered result
    renderItem={(m) => (
      <MentorCard
        variant="listed"
        {...m}
        actions={
          <Button
            variant="secondary"
            size="dense"
            loading={removing.includes(m.id)}
            loadingLabel="Removing…"
            onClick={() => remove(m)}
          >
            Remove from favorites
            <span className="sr-only">: {m.displayName}</span>
          </Button>
        }
      />
    )}
    filter={{ legend: "Stack", options: STACKS }}
    selected={selected}
    onSelectedChange={setSelected}
    noun={{ singular: "mentor", plural: "mentors" }}
    loading={isLoading}
    error={isError}
    onRetry={refetch}
    skeleton={<MentorCardSkeleton />}
    loadingLabel="Loading your favorite mentors…"
    errorTitle="Your favorite mentors did not load"
    errorMessage="Nothing was changed. Try again." // optional
    noResults={{ title: "No favorite mentors for these filters", description: "Remove a filter to see more." }}
    nothingYet={{ title: "You have not saved any mentors yet", description: "Save a mentor from the directory." }}
    notice={
      failure && (
        <Alert variant="destructive">
          <AlertTitle>The mentor was not removed</AlertTitle>
          <AlertDescription>{failure} They are still in your favorites.</AlertDescription>
        </Alert>
      )
    }
  />
</div>
```

## Known limits

- "Nothing here yet" has no create action in the directory, because a mentee cannot create a mentor. It says when mentors appear. A list the viewer can add to (windows, invitations) offers the create action.
- Filters are a checkbox group of four stacks. A filter with many values (a combobox with search) is not in the system yet.
- Paging is not designed: the pilot list is short. Thirty cards are a story; hundreds are not.
