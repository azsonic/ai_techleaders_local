# What is missing

An honest list of what the design system does not cover yet: backlog coverage first, then parts and states that were recorded as gaps during the build. Nothing here is hidden behind "ready".

**Readiness** means: **Built** (components and screens exist with states), **Proposal** (built from the brief with no specification; needs approval) or **Gap** (not designed). **Priority** is a proposal for the Product owner to decide, not a decision: **P1** blocks the first paid session, **P2** is needed in the pilot, **P3** can wait.

## Not checked

- Screen reader output for every component: roles, names and focus were checked with axe, attribute assertions and interaction tests only.
- Real mobile browsers: native date and time inputs, the on-screen keyboard with the composer, touch behavior of tooltips and popovers.
- A real operator session with the 12-hour rule, and real data volumes.
- The agent test (an agent building a new screen from these pages) was run on 2026-10-26 with the Favorite mentors screen. It produced 24 gaps, all closed in the Favorites change. A second run with a fresh agent is recorded in `.ai/runs/`. Run it again for the next new kind of screen.
