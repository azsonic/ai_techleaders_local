# What to avoid

Three kinds of mistake, each with how to recognize it on screen and in code, why it is a problem and what to use instead. `npm run check:tokens` finds the code signs of non-token values automatically; the rest are caught in review.

## 1. The product's own anti-patterns

From `lekcja-06/referencje.md`. The negative references say what DevMentor must not look like.

| Avoid                                                                        | Recognise it in code                                                                                                                          | Why                                                      | Use instead                                                                                                                          | Source              |
| ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------- |
| **A01** The typical AI startup look: purple gradients, glass cards, sparkles | `bg-gradient-to-*`, `from-*` / `to-*`, `backdrop-blur`, translucent fills (a background color with an opacity suffix), sparkle icons or SVGs | The owner finds it interchangeable with everything else. | Flat backgrounds, opaque surfaces, text labels                                                                                       | A01.1, A01.2, A01.3 |
| **NR01** A cold, undifferentiated information view                           | Primary and secondary information with the same class; gray surfaces with no warmth                                                           | Hard to tell what matters.                               | Warm gray surfaces; `font-emphasis` and the primary fill for the main action or current status, `text-muted-foreground` for metadata | R01.4, R01.5        |
| **NR02** A cluttered workplace chat shell                                    | Badges and notices spread through navigation, decorative emoji in labels, a large channel tree                                                | Competes with the conversation.                          | Booking notices next to the booking, text labels, a short labelled navigation                                                        | R02.4, R02.5, R02.6 |
| **NR03** A course or learning-journey interface                              | `<progress>`, `role="progressbar"`, module lists, certificate components                                                                      | People want an answer, not a course.                     | The question, the session and the written answer                                                                                     | N01.1 to N01.3      |
| **NR04** A rating-led mentor profile                                         | A `Star` icon, a rating field rendered as stars or badges                                                                                     | Participants distrust ratings.                           | Public-work links and relevant experience                                                                                            | N02.1, N02.2        |

## 2. Generic AI appearance

| Avoid                                        | Recognise it in code                                                  | Why                                                             | Use instead                                                      | Source                      |
| -------------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------- | --------------------------- |
| Gradients in backgrounds, text and buttons   | `bg-linear-*`, `bg-gradient-*`, `bg-clip-text text-transparent`       | The signature of A01.                                           | A semantic fill: `bg-background`, `bg-card`, `bg-primary`        | A01.1                       |
| Glass and blur                               | `backdrop-blur-*`, `bg-*/N` over an image                             | Translucent surfaces break contrast and are rejected.           | Opaque `bg-card` or `bg-popover`                                 | A01.2                       |
| Glow                                         | `shadow-*` with a palette color and an opacity suffix, `drop-shadow` | Decoration; there are no shadows in the system.                 | A 1px `border-border`                                            | A01, shape and depth        |
| Emoji instead of icons or labels             | An emoji character inside JSX                                         | Labels identify actions; emoji are decoration.                  | A text label; a Lucide icon only with a label or accessible name | R02.5                       |
| Sparkles as an AI symbol                     | `Sparkles` from `lucide-react`                                        | A01.3.                                                          | Nothing. No replacement ornament is chosen.                      | A01.3                       |
| Three identical icon cards in a row          | A grid of three `Card`s each with an icon and a heading               | The generic landing-page pattern.                               | Content that differs: a table, a list or a sentence              | A01, AC03 (proposal)        |
| Pills everywhere                             | `rounded-full` on badges, buttons and inputs                          | The system's controls and badges use the control radius (8 px). | `Badge`, `Button` as they are                                    | Stage 2 decision 2          |
| A card inside a card                         | A `Card` rendered inside another `Card`                               | Nested boxes clutter.                                           | One panel; split with a heading or a line                        | Card page                   |
| A shadow as the only way to separate content | `shadow-md` with no border                                            | Not visible to everyone and not part of the system.             | A 1px border; space between groups                               | R01.3, A01.2                |
| Everything centered                          | `text-center` on sections, `items-center` on page columns             | Centered blocks read as a landing page.                         | Left-aligned text; `EmptyState` is left aligned                  | Batch 3 decision (approved) |

## 3. Implementation mistakes

| Avoid                                           | Recognise it in code                                                                                                                                                                  | Why                                              | Use instead                                                               | Source                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------- | ------------------------------ |
| Non-token values                                | A hex, rgb, hsl or oklch color outside the token file; a palette class (a utility, a color name and a shade, or a white or black text class); an arbitrary value in square brackets | Breaks both themes and the contrast checks.      | Semantic tokens: `bg-card`, `text-foreground`, `p-panel`                  | `check:tokens`, stage 1        |
| An incidental variant                           | A new `variant` or one-off class on a base component for one screen                                                                                                                   | Two places with the same need get two looks.     | An existing variant; if two places need it, propose it (see Contributing) | Contributing                   |
| A `div` instead of a button                     | `<div onClick>`, `<span role="button">`                                                                                                                                               | No keyboard, no focus, no role.                  | `Button`, `TextLink`                                                      | WCAG 2.1.1, 4.1.2              |
| A placeholder instead of a label                | `<Input placeholder="E-mail" />` outside a `Field`                                                                                                                                    | The name disappears when typing.                 | `Field` with `FieldLabel`                                                 | WCAG 3.3.2, Form pattern       |
| Status shown only by color                      | A red or green dot or text with no words                                                                                                                                              | Not accessible; meaning lost without color.      | `Badge` with the status in words                                          | WCAG 1.4.1                     |
| A disabled button with no explanation           | `disabled` with no sentence beside it                                                                                                                                                 | People cannot learn what to do.                  | Visible reason text linked with `aria-describedby`                        | WCAG 3.3.2, stage 2 decision 4 |
| A toast for an error that needs action          | `toast(...)` on a failure                                                                                                                                                             | It disappears before the person acts.            | `Alert`, a field error or `ErrorMessage`                                  | WCAG 2.2.1                     |
| A tooltip with information essential for action | `Tooltip` around the only explanation of a rule                                                                                                                                       | Touch users never see it.                        | Text on the page                                                          | WCAG 1.4.13, Tooltip page      |
| Claiming success before the server answered     | Setting "saved" before `await`                                                                                                                                                        | The person believes something that may be false. | Show results after the server confirmed                                   | P12.1                          |
| `fetch("/api…")` in a component                 | A direct `fetch`                                                                                                                                                                      | No CSRF header, no envelope handling.            | `apiCall` from `@devmentor/ui/backend/api/api-call`                       | AGENTS.md                      |

## Known violations in the repository

`check:tokens` reports 9 findings: `packages/ui/src/frontend/hero.tsx` and `packages/app/src/app/(frontend)/page.tsx` use indigo, zinc and white palette classes and a gradient (A01). They predate the design system and are outside the design system's scope to change (rule 11); they are listed for the stage 5 report.
