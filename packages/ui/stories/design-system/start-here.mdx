# Start here: how to build a screen

This is the operating manual for DevMentor's interface. It is read by a developer building a screen, by an AI agent building a screen and by a designer checking one. Done means you can build a new screen from these pages without guessing: which component to use and why, how to compose it, which tokens to use, how each state behaves and what not to do.

An agent should read [`docs/design-system.md`](#the-agent-file) first. It has the same rules in one file.

## The product in three sentences

DevMentor connects a developer who is blocked with an experienced mentor for a paid 25 or 50 minute text session, and the product's job is to get that developer a written answer (N01.1). The interface is **clear**, **warm** and **focused** (C01 to C03): the main action or current status is stronger than the metadata (R01.5), surfaces are warm gray, flat and opaque (R01.4, A01.1, A01.2), and in a session the conversation is the center and the composer stays in view (R02.1, R02.2). It is never **cold**, **cluttered** or **generic** (AC01 to AC03): no gradients, glass or sparkles, no emoji used as interface, no course progress bars or certificates, no star ratings and no notification noise (A01, R02.4, R02.5, N01, N02).

| Character words                                                          | Anti-character                                                          |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| **Clear** (C01): readable hierarchy, author and time on every message    | **Cold** (AC01): a gray information view with no warmth or priority     |
| **Warm** (C02): warm gray surfaces, helpful wording (P01, P10.1)         | **Cluttered** (AC02): competing notices, emoji, a channel-heavy sidebar |
| **Focused** (C03): the conversation and the composer, little around them | **Generic** (AC03): the typical AI startup look                         |

Source: `lekcja-06/referencje.md`.

## Five steps to build a screen

1. **Find a pattern.** Most screens are one of these: [Form](?path=/docs/patterns-form--docs), [Filtered list](?path=/docs/patterns-filtered-list--docs), [Detail view](?path=/docs/patterns-detail-view--docs), [Deletion confirmation](?path=/docs/patterns-deletion-confirmation--docs), [Conversation](?path=/docs/patterns-conversation--docs), [Operator action](?path=/docs/patterns-operator-action--docs). Open the epic page nearest to your screen ([E01](?path=/docs/design-system-e01-mentor-supply--docs) to [E05](?path=/docs/design-system-e05-supply-gate-and-pilot--docs)) and copy its flow. All 19 screens and their states are in [Screens and state maps](?path=/docs/design-system-screens-and-state-maps--docs).
2. **Select components through [How to choose](?path=/docs/design-system-how-to-choose--docs).** Take a product component if one exists ([Components](?path=/docs/design-system-components--docs)); otherwise compose base components. Never write a new look for something that exists, and never add a component or variant that is not needed in two places ([Contributing](?path=/docs/design-system-contributing--docs)).
3. **Use semantic tokens.** Colors, spacing, type and radii come from tokens named by purpose: `bg-card`, `text-muted-foreground`, `gap-within-group`, `p-panel`, `text-interface`. Never a hex value, a Tailwind palette class (a color name with a shade, such as the zinc or indigo families), or an arbitrary value in square brackets. See [Foundations](?path=/docs/foundations-color--docs) and run `npm run check:tokens`.
4. **Design the data states.** Every screen with data has loading (skeleton and a text label), empty or "nothing here yet", error with a next step, partial data, lots of data and long text. A screen with an action also has pending, server error and offline. Success appears only after the server confirmed. Use [Screens and state maps](?path=/docs/design-system-screens-and-state-maps--docs) as the checklist.
5. **Check [What to avoid](?path=/docs/design-system-what-to-avoid--docs)** and [Usage and accessibility](?path=/docs/design-system-usage-and-accessibility--docs). Then run the checks: `npm run lint`, `typecheck`, `test`, `build`, `check:tokens`, and `test:stories` in both themes.

## All components

Every component, where to import it, when to use it and when not to. The [Components](?path=/docs/design-system-components--docs) page shows each one working.

| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Button                 | `@devmentor/ui/components/ui/button { Button }`                                                                                                                | Submit a form, confirm in a dialog, any action that changes data.                            | Navigation (use Text link); a low-priority action inside a sentence (use `variant="link"`).            |
| Text link              | `@devmentor/ui/frontend/text-link { TextLink, textLinkClassName }`                                                                                             | Go to a mentor's page, My bookings, the privacy notice, a mentor's public work (`external`). | An action that changes data (use Button).                                                              |
| Menu                   | `@devmentor/ui/components/ui/dropdown-menu { DropdownMenu, DropdownMenuTrigger, DropdownMenuContent, DropdownMenuItem }`                                       | Three or more commands for one object where one is not the main one.                         | The one main action of a screen (use a visible Button); one or two commands (use buttons or links).    |
| Text input             | `@devmentor/ui/components/ui/input { Input }`                                                                                                                  | Display name, price, link, e-mail; search and filter fields (`density="dense"`).             | Several lines (use Textarea); one of a few known values (use Select or Radio group).                   |
| Textarea               | `@devmentor/ui/components/ui/textarea { Textarea }`                                                                                                            | The booking question, a cancellation note, an operator's reason.                             | One short line (use Text input); a message in a live session (use Composer).                           |

## The agent file

`docs/design-system.md` in the repository is the same guide for an AI agent: product character, this table, the semantic tokens and their purposes, the "if then use" rules, the "what to avoid" list and the Storybook commands. `AGENTS.md` links to it.

## Storybook commands

| Command                                      | What it does                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `npm run storybook -w @devmentor/ui`         | Starts Storybook on port 6006                                             |
| `npm run build-storybook -w @devmentor/ui`   | Builds the static Storybook                                               |
| `npm run test:stories -w @devmentor/ui`      | Runs every story as a test, with accessibility checks as errors           |
| `npm run test:stories:dark -w @devmentor/ui` | The same in the dark theme                                                |
| `npm run check:tokens`                       | Finds colors, palette classes and arbitrary values outside the token file |
| `npm run check:contrast -w @devmentor/ui`    | Recalculates contrast for every supported pair in both themes             |

## Technical note

The base components come from shadcn/ui, style `base-nova`, built on Base UI (`@base-ui/react`). The product's appearance comes from `lekcja-06/referencje.md` and `lekcja-06/tokeny.md`, not from the base library.
