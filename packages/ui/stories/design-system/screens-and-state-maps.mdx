# Screens and state maps

Every backlog epic has a page with its flow, its screens and a state map: each state of each screen is one story, with its source. This page lists them all. Counts are the stories under `Product / <epic> / Screens`, counted from the built Storybook.

**Specified** means the epic has a specification in `.ai/specs/`. **Proposal** means it has none: the screens come from the brief's decisions and need approval before they are requirements.

## Reading a state map

Each epic page has one table per screen: the state, the story that shows it and the source of the state (a specification section, a decision, a rule or a reference). A screen that takes an action has pending, server error and offline states where the epic page lists them. States a screen does not have are not listed, and gaps are recorded for "What is missing" rather than assumed here.
