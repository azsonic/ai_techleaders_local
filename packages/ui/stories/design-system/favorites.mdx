# Favorites

A mentee keeps a short list of mentors to come back to, narrows it by stack and removes one when they no longer want it. **No specification exists yet.** The screen is a proposal drawn from the design system's own rules, built as the first test of whether those rules are enough for a new screen (2026-10-26). There is no backend: the list takes data by props.

## Flow

1. The mentee opens **Favorite mentors** (`/favorites`) and sees saved mentors with name, headline and stacks. Each name links to the mentor's page.
2. They narrow the list with the visible Stack filter. The count is announced.
3. They press **Remove from favorites** on a card. Only that card is pending. After the server confirms, the card goes, a toast names the mentor, and focus moves to the next card. The mentor can be saved again from their profile, so there is no confirmation dialog.

## Product work that remains

- **Not built, recorded for "What is missing":** the "save a mentor" button on the mentor page, the API and the page that loads the list, a combobox filter, and an Undo after a removal.
- The headline limit of 200 characters is confirmed by the Product owner; the field itself belongs to the mentor profile and is not in the profile form yet.
- The filter uses the four stacks the system has. A mentor with no stack matches no filter and appears only in the unfiltered list.
