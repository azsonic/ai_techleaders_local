# E04 Text session

A mentee and a mentor exchange text in a session, and the mentee answers one question afterwards. **No E04 specification exists yet.** The components and screens here are proposals drawn from the brief: decisions D10, D11, D20, D32, rules R02, R16 and the references R02.1 to R02.5, P10, P11, P12. Backlog: E04-S01 (exchange text in a session), E04-S02 (usefulness check).

## Flow

1. The mentee books (E02, E03). The booking question becomes the first message of the session.
2. At the start time both open the **Session** screen. A party is present when they open it in the first 10 minutes (R16).
3. They write to each other; each message shows its state (**Conversation** pattern).
4. When the session ends the composer says so and stays visible but disabled; both can still read.
5. The mentee answers the **Usefulness check**: did the help arrive before the deadline (D11).

## Product work that remains

- **Not designed, recorded for "What is missing":** "Report a problem" within 24 hours of the end, with its two reasons and 1000 characters (D32); attendance ("Anna has not joined yet", R16); code in messages (R01.2, P09.2); a message length limit; a keyboard shortcut to send; the operator's read-only view of a session in a dispute (D29, R13); a booking's own page with the link into the session.
- The session screen is one screen tall with a scrolling log. The application shell is not in the plan, so the header above it is a documentation helper.
- The phase is computed from `now`, which the page passes. The page decides how often to re-check; nothing on screen counts down.
- The usefulness check has three answers: the two from the brief and "I had no deadline" (approved, so a mentee without a deadline gives no false answer).
