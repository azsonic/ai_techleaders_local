# E05 Supply gate and pilot measurement

The operator sees whether enough mentors have published for paid booking to open, reads the pilot measures, and can suspend a mentor with every action logged. **No E05 specification exists yet.** The components and screens here are proposals drawn from the brief: decisions D11, D12, D16, D19, D20, D24, D25, D29 and rules R06, R13, R16. Backlog: E05-S01 (gate status), E05-S02 (timing, payments, refunds, booking source), E05-S03 (suspend a mentor, every action logged).

## Flow

1. The operator signs in with GitHub (session of at most 12 hours, D25) and opens the **Gate** page: invited, accepted and published counts and whether paid booking is open (D16).
2. The **Metrics** page shows timing, payments, refunds, booking source and the usefulness outcome, each with how it is counted (D11, D19, D20).
3. On a mentor's page the operator can **suspend** them. The dialog names the mentor, states the consequence and requires a reason (D29, R13).
4. Every operator action appears in the **Audit log** with who, when, what and why.

## Product work that remains

- **Not designed, recorded for "What is missing":** viewing a session in dispute and recording its outcome with a reason (R16, D29); the operator sign-in page and the "session expired, sign in with GitHub again" state (D25); audit log filters and paging; a way to see a mentor's cancellation reasons and counts (D34); the mentor list page that leads to a mentor's page.
- The gate state is decided on the server (D16). The component only shows it; the two-week clock per mentor is not drawn.
- The measures are examples with made-up numbers. Their definitions (median, week boundaries) are not specified yet and are proposals.
- The revoke button in the E01 invitations screen now opens `OperatorActionDialog`. A reason has at most 1000 characters (same limit as D32).
- Operator pages use the same base components as the rest of the system, as the application will build them on shadcn (AGENTS.md).
