# Spacing and layout

One step (`--spacing`, 4px) with named relationships on top. Name the relationship, never the number: `gap-within-group`, not `gap-2`.

## Spacing relationships

<Unstyled>
  <SpacingScale />
</Unstyled>

Rule of proximity: the closer two things belong together, the smaller the gap. Within a group use `--space-within-group`. Between groups use `--space-between-groups`. Between whole sections use `--space-section`. A gap larger than the one before it signals a new group (R01.1, P03).

Dense rows for browsing mentors and bookings use `--space-panel-compact`. The session conversation does not take dense packing (P03, R02.1).

## Layout at three widths

| Width   | What changes                                                                                                                                           | Source            |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------- |
| 320 px  | One column. Short labeled navigation, not a channel-style sidebar. The composer stays visible with the conversation. Page inset `--space-page-inline`. | R02.6, R02.2      |
| 768 px  | Browsing lists keep rows, with metadata beside the main information. Forms stay one column.                                                            | R01.1             |
| 1440 px | Content stays within a maximum width instead of stretching.                                                                                            | Approved proposal |

**Maximum content width (approved proposal, no reference source).** Browsing and booking pages `--size-content-browse` (72rem, class `max-w-content`). Forms and conversation `max-w-prose` (65 characters).

**A page and its frame.** A page is one `h1` and its content inside the maximum width, with `px-page-inline` at the sides and `gap-section` between sections. The header, navigation and unread count (the application shell) are not designed; the stories use `ScreenFrame`, a documentation helper that is not exported and not a product component.

**Actions inside a card.** An action on a card sits under the content, never beside the name, so it fits at 320 px. Lists of cards are one column below `md` and two from `md`.

**Not decided.** Where the composer sits when an on-screen keyboard is open (listed as a gap in the references).
