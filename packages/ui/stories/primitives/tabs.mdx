# Tabs

## 1. Purpose

Lets a person switch between a few views of the same thing on one page, such as upcoming and past bookings.

## 2. When to use

- "Upcoming", "Past" and "Cancelled" on a mentee's bookings (E02-S04).
- Two to five views of one list or one object, where one view is shown at a time.

## 3. When not to use

| Situation                                            | Use instead                                                                                              |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Moving to a different page or section of the product | Links in a navigation, so the browser history and URLs work                                              |
| Steps of a process                                   | A pattern with numbered steps, one page each                                                             |
| A choice that changes data, such as an order         | [Radio group](?path=/docs/primitives-radio-group--docs) or [select](?path=/docs/primitives-select--docs) |
| More than five views                                 | Rethink the page. A filter or separate pages fit better.                                                 |

Sources: WAI-ARIA Authoring Practices (tabs), R01.1 (many items readable together).

## 5. Variants

There is one flat underline style. A filled or rounded tab would be a pill, which the references reject (A01).

## 6. States

<Canvas of={Stories.StateMatrixStory} />

| State          | Behavior                                                                                                                                           | Source                |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| Default        | Muted text, transparent bar.                                                                                                                       | R01.5                 |
| Hover          | Text turns to `--foreground`. Opaque, no movement.                                                                                                 | R01.5, P11.1          |
| Focus          | 2px ring in `--ring`, offset 2px.                                                                                                                  | tokens.md, WCAG 2.4.7 |
| Selected       | 2px `--foreground` bar and semibold text. Never color alone.                                                                                       | WCAG 1.4.1            |
| Disabled       | Muted text and a `not-allowed` cursor. It looks like an unselected tab, so do not disable a tab: remove it, or show its panel with an empty state. | WCAG 1.4.1, 3.3.2     |
| Pressed        | Same as hover. There is no movement on press.                                                                                                      | P11.1                 |
| Loading, error | A panel shows its own skeleton or error state. The tabs themselves do not load.                                                                    | P12.2                 |

## 7. Behavior and accessibility

- Role: `tablist` of `tab`s, each controlling a `tabpanel` (WAI-ARIA tabs). Give the list an `aria-label`.
- Keyboard: Tab enters the list on the selected tab. Left and Right Arrow move to the next tab and select it at once, because panels appear without delay (automatic activation). Tab then moves into the panel.
- The selected tab has `aria-selected="true"`.
- Tab height is 32px (WCAG 2.5.8).

## 8. Content

- One or two words per tab, in the person's terms: "Upcoming", "Past", "Cancelled".
- Do not put counts or icons in tabs unless a screen needs them.
- Long labels never wrap. The list scrolls sideways when tabs do not fit.

<Canvas of={Stories.ManyTabsNarrow} />

## 9. Responsiveness

- 320px: the list scrolls horizontally inside its own border; the page does not.
- 768px and 1440px: the tabs sit left-aligned, with `--space-between-groups` between them.

## 10. API

Parts: `Tabs` (`value`, `defaultValue`, `onValueChange`), `TabsList`, `TabsTrigger` (`value`, `disabled`), `TabsContent` (`value`). The controls above belong to the story wrapper.

## 11. Code

```tsx
<Tabs defaultValue="upcoming">
  <TabsList aria-label="My bookings">
    <TabsTrigger value="upcoming">Upcoming</TabsTrigger>
    <TabsTrigger value="past">Past</TabsTrigger>
    <TabsTrigger value="cancelled">Cancelled</TabsTrigger>
  </TabsList>
  <TabsContent value="upcoming">{/* booking list */}</TabsContent>
  <TabsContent value="past">{/* booking list */}</TabsContent>
  <TabsContent value="cancelled">{/* booking list */}</TabsContent>
</Tabs>
```
